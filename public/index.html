01 / From event to image

Publish your napplet.
Napshot handles the picture.

  1. 01

    Watch

    Find root and named manifests on configured relays. Keep the author’s usable screenshot when one already exists.

  2. 02

    Capture

    Render the napplet in a sandboxed Paja shell and capture its iframe. A fresh, signed-out view, with no personal account attached.

  3. 03

    Mirror

    Upload the same PNG to at least two Blossom servers. The content hash identifies the image across every copy.

  4. 04

    Label

    Publish a signed NIP-32 event referencing the exact napplet event. Shells can discover the picture without changing the manifest.

Root 15129 + named 35129 only. Snapshots are excluded. Captures show the initial view; features requiring an account or network data may appear empty.

02 / For shell implementers

One lookup.
A better app shelf.

Use the author’s screenshot first. When it’s missing, look for a label from a Napshot signer you trust.

  1. Query kind 1985 by the manifest’s exact event ID, label namespace, and trusted signer.
  2. Verify the signature, target, and screenshot hash. An address tag alone doesn’t identify a revision.
  3. Fetch the PNG from the listed Blossom servers. Verify its SHA-256 before displaying it; try another mirror if needed.

A screenshot is a preview, not an endorsement or a guarantee that a napplet is safe.

RELAY FILTERNIP-32 / 1985 
{
  "kinds": [1985],
  "authors": [trustedSigner],
  "#e": [manifest.id],
  "#L": ["#screenshot"]
}
The screenshot tag carries the image hash, MIME type, dimensions, and size. server tags locate its mirrors.
